1. ARCHITECTURE & PORT DETAILS
================================================================================
- Worker Host Service: NewHorizon.Automation.Worker
- Default Port: Configured via AutomationAgent:Host:ManagementApiPort (e.g., 5050)
- Base URL: http://localhost:5050 (or http://127.0.0.1:5050)
- Endpoints serve both the WebApp2 frontend (ERP browser users) and automated 
  machine callers (schedulers, timers, CLI scripts).

================================================================================
2. AUTHENTICATION & AUTHORIZATION MECHANISMS
================================================================================

A. API KEY AUTHENTICATION (Machine callers / Schedulers)
   - Header: X-Automation-Api-Key: <InboundApiKey>
   - Configured in: appsettings.json -> AutomationAgent:Host:InboundApiKey
   - Grants access to machine management and trigger endpoints.
   - Bypasses user-level ERP Role Management checks.

B. ERP JWT BEARER TOKEN (Browser users in WebApp2)
   - Header: Authorization: Bearer <ERP_JWT_TOKEN>
   - Token generated when ERP user logs into WebApp2.
   - Configured in: appsettings.json -> AutomationAgent:InboundJwt:SigningKey

C. ERP ROLE MANAGEMENT FORM PERMISSIONS (Checked for Bearer token users)
   - Form 011171 ("PO Automation Configuration"):
     * 'I' (Inquiry): View settings, view eligible indents.
     * 'E' (Edit): Modify settings, enable/disable switches, trigger "Run now".
   - Form 011172 ("PO Automation Run History"):
     * 'I' (Inquiry): Access conversion history, summary KPI analytics, job retries.

3.1 PO AUTOMATION SETTINGS (INDENT -> PO)
--------------------------------------------------------------------------------
Governs automated conversion of Material (Regular, Capital) and Service indents.

[1] GET /api/automation/po-automation/
    - Auth: Bearer Token (Form 011171 'I')
    - Description: Lists configuration rows for all 3 indent types: Regular, Capital, Service.
    - Status: 200 OK
    - Sample Response:
      [
        {
          "indentType": "Regular",
          "runMode": "Both",
          "scheduleTime": "02:00:00",
          "sites": "1,2",
          "indentNumbers": null,
          "isActive": true,
          "dryRun": false,
          "maxIndentsPerRun": 50,
          "lastScheduledRunDate": "2026-10-06",
          "lastTriggeredAtUtc": "2026-10-06T02:00:05Z",
          "lastRunStatus": "Completed",
          "lastRunReference": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
          "updatedAtUtc": "2026-10-01T10:00:00Z",
          "updatedBy": "admin"
        }
      ]

[2] GET /api/automation/po-automation/{indentType}
    - Auth: Bearer Token (Form 011171 'I')
    - Path param: indentType ("Regular" | "Capital" | "Service")
    - Description: Returns config for a single indent type.

[3] PUT /api/automation/po-automation/enabled
    - Auth: Bearer Token (Form 011171 'E')
    - Description: Master on/off toggle for all 3 indent types in one transaction.
    - Request Body:
      {
        "enabled": true
      }
    - Status: 200 OK

[4] PUT /api/automation/po-automation/{indentType}
    - Auth: Bearer Token (Form 011171 'E')
    - Path param: indentType ("Regular" | "Capital" | "Service")
    - Description: Updates settings for a specific indent type.
    - Request Body:
      {
        "runMode": "Both",
        "scheduleTime": "02:30:00",
        "clearScheduleTime": false,
        "sites": "1,2",
        "indentNumbers": "26-27/PI/NF1/000162",
        "clearIndentNumbers": false,
        "isActive": true,
        "dryRun": false,
        "maxIndentsPerRun": 25,
        "clearMaxIndentsPerRun": false
      }
    - Status: 200 OK

3.2 GRN AUTOMATION SETTINGS (PO -> GRN)
--------------------------------------------------------------------------------
Governs automated Goods Receipt Note generation from authorised POs.

[5] GET /api/automation/grn-automation
    - Auth: Bearer Token (Form 011171 'I') OR X-Automation-Api-Key
    - Description: Gets current PO -> GRN settings.
    - Status: 200 OK
    - Sample Response:
      {
        "isActive": true,
        "runMode": "Both",
        "scheduleTime": "04:00:00",
        "receiptMode": "Complete",
        "invoiceNumber": "INV-AUTO-01",
        "sites": "1,2",
        "poTypes": ["Regular", "Capital"],
        "poNumbers": null,
        "dryRun": false,
        "maxPosPerRun": 25,
        "lastScheduledRunDate": "2026-10-06",
        "lastTriggeredAtUtc": "2026-10-06T04:00:02Z",
        "lastRunStatus": "Completed",
        "lastRunReference": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
        "updatedAtUtc": "2026-10-05T14:30:00Z",
        "updatedBy": "admin"
      }

[6] PUT /api/automation/grn-automation
    - Auth: Bearer Token (Form 011171 'E') OR X-Automation-Api-Key
    - Description: Updates GRN settings. NOTE: If isActive=true and scheduleTime 
      is omitted/null, an immediate "Run Now" execution is triggered synchronously!
    - Request Body:
      {
        "isActive": true,
        "runMode": "Both",
        "scheduleTime": "04:00",
        "receiptMode": "Complete",
        "invoiceNumber": "INV-AUTO-01",

        "dryRun": false,
        "maxPosPerRun": 25,
        "poTypes": ["Regular"],
        "poNumbers": "26-27/TE/NF1/000190"

    - Response: { "config": { ... }, "execution": { ... } or null }

[7] PUT /api/automation/grn-automation/enabled
    - Auth: Bearer Token (Form 011171 'E') OR X-Automation-Api-Key
    - Request Body: { "enabled": true }

[8] PUT /api/automation/grn-automation/po-types
    - Auth: Bearer Token (Form 011171 'E') OR X-Automation-Api-Key
    - Request Body: { "poTypes": ["Regular", "Capital"] }

[9] PUT /api/automation/grn-automation/po-numbers
    - Auth: Bearer Token (Form 011171 'E') OR X-Automation-Api-Key

4. HISTORY, MONITORING & RUN TRACKING APIS

--------------------------------------------------------------------------------
4.1 PROCESS JOB HISTORY (INDENT -> PO)
--------------------------------------------------------------------------------

[13] GET /api/process-jobs
     - Auth: Bearer Token (Form 011172 'I') OR X-Automation-Api-Key
     - Description: Paged grid of conversion job executions with full status.
     - Query Parameters:
       * search: string (document/indent reference)
       * workflow: string (e.g. "IndentToPurchaseOrder")
       * status: "Pending" | "Running" | "Completed" | "Failed" | "Cancelled" | "Skipped"
       * company: string
       * trigger: "Api" | "Manual" | "Timer" | "Chatbot" | "UserPrompt" | "ErpPush"
       * stage: "Discovery" | "Allocation" | "Drafting" | "Authorisation" | "Finalisation"
       * indentType: "Regular" | "Capital" | "Service"
       * from, to: ISO 8601 UTC timestamps
       * page: integer (default 1)
       * pageSize: integer (default 50, max 200)
     - Response: PagedResult with items containing jobId, indentId, document, poNumber, durationMs, status.

[14] GET /api/process-jobs/{jobId:guid}
     - Auth: Bearer Token (Form 011172 'I') OR X-Automation-Api-Key
     - Description: Detailed breakdown of one execution, including stage timeline, 
       vendor group outcomes, and error diagnostics.

[15] GET /api/process-jobs/indent/{indentId:long}
     - Auth: Bearer Token (Form 011172 'I') OR X-Automation-Api-Key
     - Query param: ?indentType=regular|capital|service (optional disambiguation)
     - Description: History of all attempts made for a given indent ID.

[16] POST /api/process-jobs/{jobId:guid}/retry
     - Auth: Bearer Token (Form 011172 'I') OR X-Automation-Api-Key
     - Query param: ?triggeredBy=username
     - Description: Re-attempts the same indent as a brand new execution.

[17] GET /api/process-jobs/runs
     - Auth: Bearer Token (Form 011172 'I') OR X-Automation-Api-Key
     - Query params: module, trigger, status, from, to, page, pageSize
     - Description: Lists conversion trigger runs across Indent -> PO and PO -> GRN.

[18] GET /api/process-jobs/runs/{runId:guid}
     - Auth: Bearer Token (Form 011172 'I') OR X-Automation-Api-Key
     - Description: Run details and associated executions or GRN receipts.

--------------------------------------------------------------------------------
4.2 PO -> GRN HISTORY
--------------------------------------------------------------------------------

[19] GET /api/automation/po-to-grn/history
     - Auth: Bearer Token OR X-Automation-Api-Key
     - Query params: trigger, status, from, to, page, pageSize
     - Description: Lists historical PO -> GRN sweep runs. Each item includes:
       * runId, workflow ("PoToGrn"), status, trigger
       * posExamined, grnsCreated
       * grnNumber: string (created GRN number, e.g. "26-27/GR/NF1/000045")
       * grnNumbers: string[] (array of created GRN numbers)
       * poNumbers: string (the PO numbers received)

[20] GET /api/automation/po-to-grn/history/{runId:guid}
     - Auth: Bearer Token OR X-Automation-Api-Key
     - Description: Returns details of a PO -> GRN run, including receipt lines.

[21] GET /api/automation/po-to-grn/receipts
     - Auth: Bearer Token OR X-Automation-Api-Key
     - Query params:
       * search: string (matches PO number, GRN number, or vendor code)
       * status: "Created" | "Skipped" | "Failed"
       * from, to: ISO 8601 UTC timestamps
       * page, pageSize: integers (pagination)
     - Description: Detailed item-level history of every individual PO received into GRN, 
       including poNumber, grnNumber, vendorCode, linesReceived, status, reason, recordedAtUtc.

[21.1] GET /api/automation/po-to-grn/dashboard (alias: /api/automation/po-to-grn/dashbord)
     - Auth: Bearer Token OR X-Automation-Api-Key
     - Query params: days (default: 30), from, to
     - Description: PO -> GRN composite dashboard containing summary KPIs, 30-day zero-filled
       trend metrics, lastCompletedJob, lastExecution (with stage steps, validation checks, lines),
       and recentJobs list.

[22] GET /api/automation/runs
     - Auth: Bearer Token OR X-Automation-Api-Key
     - Query params: module ("po-to-grn" | "indent-to-po"), trigger, status, from, to, page, pageSize
     - Description: Combined unified view of runs across all modules. PO -> GRN runs include
       grnNumber, grnNumbers, and poNumbers.

[28] POST /api/process-jobs
     - Auth: Bearer Token (Form 011172 'I') OR X-Automation-Api-Key
     - Description: Starts a conversion and explicitly persists complete execution history.

         "indentTypes": ["Regular"],
         "sites": [1],
         "maxIndents": 1,
         "trigger": "Manual",

[30] POST /api/automation/po-to-grn
     - Auth: X-Automation-Api-Key

         "receiptMode": "Complete",

         "dryRun": false

[31] POST /api/automation/run-now
     - Auth: X-Automation-Api-Key
     - Description: Manually triggers an AutoShop cycle immediately bypassing schedule.
     - Response: { "started": true, "jobId": "...", "reason": "Enqueued manually" }

8. PRACTICAL CALLING INSTRUCTIONS (cURL & POWERSHELL)
================================================================================

--- cURL EXAMPLES ---

# 1. Check Service Health
curl -X GET http://localhost:5050/health

# 2. Preview Eligible Indents (using API Key)
curl -X GET "http://localhost:5050/api/automation/indent-to-po/eligible?sites=1&indentTypes=regular" \
  -H "X-Automation-Api-Key: YOUR_API_KEY"

# 3. Convert Indents to PO (Dry Run)
curl -X POST "http://localhost:5050/api/automation/indent-to-po?trigger=manual" \
  -H "X-Automation-Api-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"indentTypes": ["Regular"], "dryRun": true}'

# 4. Convert Indents to PO (Live Run)
curl -X POST "http://localhost:5050/api/automation/indent-to-po?trigger=manual" \
  -H "X-Automation-Api-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"indentTypes": ["Regular"], "dryRun": false}'

# 5. Get Run History Summary (using ERP User Bearer Token)
curl -X GET "http://localhost:5050/api/process-jobs/summary" \
  -H "Authorization: Bearer YOUR_ERP_JWT_TOKEN"

# 6. Trigger PO -> GRN Receiving
curl -X POST "http://localhost:5050/api/automation/po-to-grn?trigger=manual" \
  -H "X-Automation-Api-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"receiptMode": "Complete", "dryRun": false}'


--- POWERSHELL EXAMPLES ---

# 1. Fetch Dashboard Stats
$headers = @{ "X-Automation-Api-Key" = "YOUR_API_KEY" }
Invoke-RestMethod -Uri "http://localhost:5050/api/automation/dashboard" -Headers $headers -Method GET

# 2. Enable / Disable PO Automation Master Switch
$headers = @{
    "Authorization" = "Bearer YOUR_ERP_JWT_TOKEN"
    "Content-Type"  = "application/json"
}
$body = @{ enabled = $true } | ConvertTo-Json
Invoke-RestMethod -Uri "http://localhost:5050/api/automation/po-automation/enabled" -Headers $headers -Method PUT -Body $body

# 3. Query Process Job History Grid
$headers = @{ "X-Automation-Api-Key" = "YOUR_API_KEY" }
$grid = Invoke-RestMethod -Uri "http://localhost:5050/api/process-jobs?page=1&pageSize=20" -Headers $headers -Method GET
$grid.items | Format-Table jobId, document, indentType, status, poNumber

# 4. Trigger PO -> GRN Receipt Run
$headers = @{
    "X-Automation-Api-Key" = "YOUR_API_KEY"
    "Content-Type"         = "application/json"
}
$body = @{
    poNumbers   = @("26-27/TE/NF1/000190")
    receiptMode = "Complete"
    dryRun      = $false
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://localhost:5050/api/automation/po-to-grn?trigger=manual" -Headers $headers -Method POST -Body $body
